# 旅衡 MoonTrip

**杭州 / 成都旅行规划测试版 · MoonBit 驱动**

选择城市，描述自己的旅行风格和习惯，比较几种方案，再选定心仪地点、调整时间并查看预算。
MoonTrip 是以 **MoonBit 为主要实现语言** 的开源应用：AI 负责整理需求，MoonBit 负责推荐、约束校验、行程安排和费用计算，最后由用户决定怎么走。

[在线试用](https://kleinrat.github.io/Traveling/) · [测试记录](docs/testing-2026-10-11.md) · [运行检查](https://github.com/Kleinrat/Traveling/actions/workflows/ci.yml) · [MIT 许可证](LICENSE)

## 当前版本

首版聚焦 **杭州、成都**。首次打开会载入随项目提供的地点来源资料，不需要配置密钥就能手动规划、比较方案、调整行程和导出。

| 能力 | 公网测试版 | 本地运行版 |
|---|---|---|
| 两城地点资料、旅行模式和条件筛选 | 支持 | 支持 |
| 比较方案、选地点、调整日期 / 时间、预算和导出 | 支持 | 支持 |
| 地点 / 时间锁定、调整预览、撤销、简化路线图 | 支持 | 支持 |
| 已查询路线的省时 / 省钱 / 顺序建议 | 可用已有候选，本版不联网查路线 | 配置高德后可查询候选 |
| AI 理解旅行风格与习惯 | 未启用 | 配置 AI 服务后支持 |
| 高德地点查询、逐段交通候选 | 未启用 | 配置高德 Web 服务密钥后支持 |

公网版运行在 GitHub Pages，只发布浏览器资源和地点快照。密钥和本地服务不会随页面发布。

## 三种旅行模式

| 模式 | 默认安排 | 推荐侧重 |
|---|---|---|
| 懒人旅行 | 10:00–18:00，每天最多 2 个景点，站间休息 45 分钟 | 美食优先、减少转场、留出休息 |
| 特种兵旅行 | 07:00–22:00，每天最多 6 个景点，站间休息 5 分钟 | 早出晚归，在可行条件下安排更多景点 |
| 周末轻旅行 | 2 天，09:00–18:00，每天最多 3 个景点 | 每日接驳最多 60 分钟，已查询路程最多 10 公里 |

模式是可修改的起点。城市、兴趣、饮食限制、亲子 / 雨天条件和心仪地点会保留；实际站数取决于候选资料、时间和预算。

“你想遇见什么”提供自然、文化、历史、美食、摄影、城市、海边、古镇、博物馆和亲子兴趣。
还可设置慢节奏、紧凑打卡、室内 / 室外、雨天友好、步行友好、亲子适合和预算优先。
这些标签覆盖可复用规划库的输入范围；两城现有资料不保证满足每个标签。

## 怎么使用

1. **选城市与节奏**：选择杭州或成都，填写天数、作息和每人规划预算，选一种旅行模式，或自行调整条件。
2. **描述习惯**：本地配置 AI 后，点击“整理我的需求”。助手生成条件提议，核对后点击“确认条件并生成行程”；也可以直接使用手动条件。
3. **先选地点**：标记“必去、备选、不去”，可指定某一天，选完再点击“按我的选择生成”。指定日期视为必去；备选由系统择优安排。
4. **调整并锁定**：每站可以锁定地点与日期、锁定开始时间；拖动或 ↑↓ 调整当天顺序，或填写日期和时刻。每次先预览，再接受或忽略；冲突会解释原因并保留原计划。
5. **逐段选择交通**：本地点击“查询每段交通候选”，查询步行与公交 / 地铁方案。每段比较时长、费用、步行量和换乘，预览后选定，也可锁定这段交通。查询本身不会改动安排。
6. **决定是否优化**：点击“看看可行的优化”，逐条预览省时、省钱或相邻景点顺序建议。计算由 MoonBit 完成，只推荐经过约束校验的改进；原计划始终保留到你接受。接受后可“撤销上一次调整”（当前会话最多 20 次）。
7. **查看简图与预算、导出**：按天查看坐标示意图，点击编号看地点详情；绿色为景点、暖色为餐厅，直线不表示真实道路。填写人数、往返交通和全团预算，导出 JSON、Markdown 或离线路书。

地点、锁定安排、已选交通与手动行程保存在当前浏览器。已查询交通在一小时后失效，需重新查询；撤销记录只保留当前会话。
重新生成会保留“必去 / 不去”及锁定约束，未锁定的时刻可能改变。切换城市、导入资料或恢复示例会重置当前地点选择与锁定，操作可在当前会话撤销。
旧版保存计划若含虚构示例，可点击“载入杭州真实资料”或“载入成都真实资料”替换该城示例。

高德返回的公交 / 地铁方案每次最多保留 5 个可用选项，步行另查；不是完整交通方案枚举。字段缺失的步行量和换乘次数显示“未知”，缺失票价的方案不参与比较。
顺序建议只尝试相邻景点交换；本地至多为 3 次交换补充 9 个方向的路线查询，查询失败或新顺序不可行就不推荐。算法不保证全局最优，也不提供实时导航。

## 地点与餐厅资料

截至 **2026-10-11**，随项目提供的来源快照如下：

| 城市 | 景点记录 | 餐饮记录 | 可试规划 | 待补充 |
|---|---:|---:|---:|---:|
| 杭州 | 21 | 14 | 21（9 个景点、12 家餐饮） | 14 |
| 成都 | 20 | 13 | 15（6 个景点、9 家餐饮） | 18 |

“可试规划”表示记录具备当前规划需要的费用、坐标和营业窗口，**不代表实地核验或实时营业保证**。
每条记录保留地址、GCJ-02 坐标、来源链接和查询日期；停留时长是可调整的规划建议。
餐厅消费来自高德人均消费线索，免费公共游览区另附费用依据。关键词按地点和餐饮品牌选取，不是热度排行榜。

- 餐厅候选排除酒店、宾馆和机场餐饮，每个查询品牌选一个中心城区候选。
- 列表及行程按名称规则过滤同品牌分店和高度相似的短品牌名；相似名称不代表同一企业，规则也不能识别所有品牌别名。
- 午餐窗口为 **11:00–14:00**，晚餐为 **17:00–21:00**，可分别开启；每天每顿最多一个餐厅，全程避免重复。
- 未安排的餐次会提示原因；预算只包含实际安排的用餐。
- 缺少费用、复杂营业日历或分时预约的地点保留在“待核对地点”，不会自动进入行程。成都大熊猫繁育研究基地目前也在待补充列表中。
- 当前来源资料没有擅自标注素食、不辣或亲子适合；启用这些硬条件前，需要补充核实过的标签。室内场馆资料不足时，雨天筛选可能没有可行景点。

原有 23 条原创虚构资料保留用于测试或主动点击“恢复示例”，不作为真实出行依据。
当前没有接入小红书、抖音或大众点评内容。

### 核对和补充资料

本地配置高德后，“真实地点资料”面板可查询杭州、成都，也可勾选两城批量查询。
每城查询至多 20 个景点和 20 家餐厅；只取有限候选，无法覆盖整座城市。

查询结果先进入待核对列表。点击“填写并核对”，补充费用、可安排时间、适合人群与来源笔记，确认后加入候选。
高德人均消费不等于景点门票，未知费用不会按免费处理，缺失时段不会按全天开放处理。
也可手动添加景点 / 餐厅，或导入 JSON；“导出我的地点资料”会保存候选与待补充记录。

维护者可在本地更新来源快照：

```sh
python3 scripts/collect_hangzhou.py
python3 scripts/collect_chengdu.py
```

这两个脚本需要高德密钥，不调用 AI。部分成都免费游览区依据来自 2019 年成都发布资料，原文日期随记录保留，出行前需复核。

## 预算口径

**当前不考虑住宿。**

- **每人规划预算**：用于自动安排景点、餐饮和市内接驳。
- **全团总账**：景点、餐饮、市内接驳和每人往返交通分别乘人数后汇总，展示全团总额与每人分摊估算。
- **全团预算**：用于显示余额或超额提示，不会自动改变活动预算或删减地点；填写 0 表示未设置。
- 往返交通默认为 0，需要用户按实际情况补充。首站尚未计入出发点到景点的接驳。
- 消费和票价均为来源估算；额外购物、排队、游船、观光车等未明确列入的项目需自行补充。

金额采用每人整元人民币。路线时长向上取整到分钟，公交票价向上取整到整元；缺失票价会报错，不按免费处理。

## 本地运行

需要 **MoonBit、Node.js 22+、Python 3.9+**。使用浏览器原生界面，无需安装 npm 依赖。
MoonBit 工具链可从 [官方下载页面](https://www.moonbitlang.com/download/) 安装。

```sh
git clone https://github.com/Kleinrat/Traveling.git
cd Traveling
sh scripts/build.sh
python3 scripts/serve.py
```

在浏览器打开 **http://127.0.0.1:8787/**。通过本地服务访问页面；直接打开 `web/index.html` 无法正常读取接口和地点快照。
构建生成的 `web/engine.js` 来自 MoonBit 源码，不提交到仓库。
本地验证过的工具链版本为 `moon 0.1.20260920`。

### 配置 AI 与高德

```sh
cp .env.example .env
```

按需编辑本机 `.env`：

```dotenv
AI_API_KEY=填写自己的AI服务密钥
AI_BASE_URL=https://api.moonshot.cn/v1
AI_MODEL=kimi-k2.6
AMAP_API_KEY=填写自己的高德Web服务密钥
PORT=8787
```

不使用的密钥字段留空。环境变量优先于 `.env`；修改配置后重启本地服务。
`.env` 已被 Git 忽略，配置只由本地服务读取，不进入浏览器或公开产物。
若 Node 不在默认路径，可设置 `MOONTRIP_NODE=/absolute/path/to/node`。

AI 支持 Kimi K2.6，也可配置提供 `/chat/completions` 与 JSON 输出的兼容服务；兼容性需按服务商验证。
Kimi 请求使用非思考模式。发送给模型的是当前偏好和用户输入的需求文本，餐厅来源资料不随请求发送。
AI 提议须由用户确认，不会更改已经选定 / 排除的地点，也不能绕过 MoonBit 的范围校验。

高德密钥需要选择 **Web 服务** 类型。地点查询和步行 / 公交地铁路线请求均经本地服务发送。
已查询路段按方向、坐标和交通方式缓存一小时；重新查询后由 MoonBit 校验接驳、用餐、预算与每日路程。

## 三个使用场景

1. **成都懒人旅行**：两天、10:00–18:00、饮食不限，每天最多两个景点；选休闲地点，比较不同餐厅的午晚餐与预算。
2. **杭州特种兵旅行**：两天、07:00–22:00，设置更多景点；锁定心仪地点，在开放窗口与预算内调整顺序和时间。
3. **杭州周末轻旅行**：两天，较小接驳和路程上限；选择地点后查询路线，调整日期和费用，导出离线路书。

以上流程可使用随项目提供的资料。无法满足条件时，页面会给出缺失或冲突说明，用户可调整条件或补充地点。

## 实现结构

```text
src/engine/       MoonBit 模型、评分、约束、餐饮安排、路线重排与预算
src/assistant/    MoonBit AI 提示契约与输出校验
src/api/          MoonBit JSON 接口，编译为 JavaScript 模块
src/demo/         原创虚构测试资料
src/main/         可运行的 MoonBit 示例
web/              浏览器界面与两城地点来源快照
scripts/          本地 HTTP 传输、来源采集、构建与检查
.github/workflows/ 自动检查和 GitHub Pages 发布
```

推荐和校验的核心逻辑由 MoonBit 实现。JavaScript 处理界面与浏览器交互，Python 负责网络传输、来源字段整理和本地服务。

### 规划接口与数据

MoonBit 使用示例见 [src/main/main.mbt](src/main/main.mbt)。编译后的主要 JSON 入口：

| 接口 | 用途 |
|---|---|
| `plan_with_preferences_json` | 按条件、模式、餐次和路线资料规划 |
| `alternatives_with_preferences_json` | 比较三种推荐取向 |
| `edit_plan_json` | 校验手动日期、顺序和开始时间 |
| `choose_plan_json` | 三态地点选择、指定日期与锁定约束 |
| `arrange_plan_json` | 按数组顺序重排或精确校验，保留锁定时刻 |
| `suggestions_json` | 基于路线候选生成可预览的改进方案 |
| `route_options_json` | 校验交通候选及可选步行量、换乘数 |
| `reflow_plan_json` | 保留地点和日期，按路线重新编排时间 |
| `trip_cost_json` | 计算人数、往返交通和全团预算 |
| `route_query_json` / `route_result_json` | 校验路线请求及高德结果 |

旧入口 `plan_json`、`alternatives_json` 继续兼容。成功返回 `{"ok":true,"plan":...}` 或对应结果，失败返回 `{"ok":false,"errors":[...]}`。
旅行规划接口可传入 `meals: {lunch, dinner}` 和 `routing: {mode, strict, distance_limit, routes}`；路程单位为米。

景点和餐厅统一使用 `Place`。导入支持 `Place[]` 或含 `places` 的导出对象；导入文件会加载地点资料，不会完整恢复导出行程的条件与手动安排。
下例只是格式示例，费用、来源和标签须替换为核对过的资料：

```json
[
  {
    "id": "my-restaurant",
    "name": "自定义餐厅",
    "city": "杭州",
    "district": "上城区",
    "kind": "food",
    "tags": ["美食"],
    "cost": 50,
    "duration": 60,
    "open": 660,
    "close": 1260,
    "windows": [{"open": 660, "close": 840}, {"open": 1020, "close": 1260}],
    "indoor": true,
    "family": false,
    "location": "120.169899,30.239827",
    "url": "https://example.com/location",
    "source": "填写费用、营业时段的依据及核对日期"
  }
]
```

时间为午夜起分钟数，例如 09:00 为 540。`windows` 可选，表示分段营业；未提供时使用 `open` / `close`，有分段时避开午休或闭店间隙。
重复 ID、异常费用、非法时间、缺失来源或非 HTTP(S) 来源链接会被拒绝。

## 当前边界

- 使用确定性的贪心规划，不保证全局最优；无法安排也不证明不存在其他可行行程。
- 未查询路线时使用片区估算：同片区 15 分钟 / 8 元，跨片区 35 分钟 / 15 元。未知距离不计入“已查询路程”，因此该上限不代表完整行程总距离。
- 步行友好的已查询路段须为步行且不超过 1.5 公里；未查询路段仍是估算。
- 未自动核验天气、闭馆日、节假日、预约名额和排队；地图查询也不是出行当天交通保证。
- 目前没有住宿规划、社交平台内容接入或公网 AI 后端；重点是两城的可选择、可调整、可解释行程。
